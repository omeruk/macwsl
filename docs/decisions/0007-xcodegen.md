# 0007: The app's Xcode project is generated with XcodeGen

- Status: Accepted
- Date: 2026-10-21

## Context

The terminal app, maw, is a `.app` bundle. `CLAUDE.md` uses Swift Package Manager for
everything except the bundle, because SwiftPM cannot produce one: it has no notion of an
`Info.plist`, an asset catalog, bundled fonts, entitlements, or code signing of an
application. The bundle therefore needs an Xcode project.

An Xcode project is a directory whose essential file, `project.pbxproj`, is an old-style
property list of objects that refer to each other by 24-character identifiers. Xcode rewrites
it on almost every change to the project, including changes that are only incidental, such
as the order of files in a group.

The options considered:

1. **Commit a hand-maintained `.xcodeproj`.** A one-line change in Xcode, such as adding a
   file, produces a diff of several unrelated hunks of identifiers. Reviewers cannot tell
   whether a build setting changed, and merge conflicts in the file have to be resolved by
   hand, with no way to check the result except opening it in Xcode.
2. **Use a Swift package as the app.** SwiftPM can build an executable that calls
   `NSApplicationMain`, but not a signed bundle with resources and entitlements. Scripts
   that assemble the bundle around the executable would reimplement part of Xcode's build
   system.
3. **Generate the project from a small, reviewable specification.** XcodeGen and Tuist do
   this. Tuist is itself a Swift package with its own dependency graph and project
   manifest language; XcodeGen reads a single YAML file and has no other inputs.

## Decision

Option 3 with XcodeGen. `App/project.yml` is the only committed description of the Xcode
project. `App/maw.xcodeproj` is generated by running `xcodegen` in `App/`, and is
git-ignored.

- **XcodeGen is a build tool, not a dependency.** Nothing in the app links against it, and
  the generated project builds without it. It is installed with Homebrew, on developer
  machines and in CI.
- **The specification stays thin.** It describes one application target, `maw`, with its
  `Info.plist`, entitlements, asset catalog, bundled fonts, and a pre-build step that checks
  the fonts' SHA-256 digests. All app logic lives in the `MawTerminalKit` package (see
  `docs/decisions/0008-app-package.md`), which the project references as a local package.
- **A minimum version is recorded.** `options.minimumXcodeGenVersion` in `project.yml` makes
  an older XcodeGen fail with a message instead of generating a different project.

## Consequences

- A change to the project is a change to `project.yml`, which reads as a list of settings.
- Contributors run `xcodegen` after checking out a branch that changes `project.yml`. The
  README states this.
- The CI app job installs XcodeGen with Homebrew, so it uses the newest release. The job
  prints the version it used.
